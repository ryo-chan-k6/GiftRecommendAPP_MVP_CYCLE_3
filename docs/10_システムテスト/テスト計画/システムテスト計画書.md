## 2. 目的

MVP の主要業務シナリオが End-to-End で成立することを確認できる状態を定義する。

あわせて、ユーザー導線上の Public API 呼び出しが Orval 生成 client 経路で成立することを確認対象に含める（全体計画 §7.5.1）。

---

## 3. 実施環境の役割（本計画の前提）

| 環境 | 本計画での役割 | 証跡 |
| --- | --- | --- |
| **Layer2 GHA** | システムテストの **主実施環境**（固定シナリオ・自動／半自動、fixture 既定） | `workflow_dispatch` artifact / job summary → `docs/10_システムテスト/テスト結果/` へ要約転記 |
| **簡易 stg** | 通し確認・人手で必要な補完（受入前）。受入証跡そのものは受入工程 | 必要時のみ。受入合格には [受入環境方針](../../13_受入テスト/テスト計画/受入環境方針.md) に従う |
| local | 実装・デバッグ。システムテスト合格証跡には **数えない** | — |

### 3.1 全体計画 §7.5 との関係

全体テスト計画書 §7.5.3 は実施環境を `staging` と記載する。一方、テスト環境設計書および受入環境方針は、システム／固定品質を **Layer2**、受入・多様人手を **簡易 stg** とする。

本計画は受入環境方針の細分化に合わせ、**システムテストの主戦場を Layer2** とする。全体計画本文の staging 記述との矛盾解消は後続 Task 候補とし、本 Task では並走を明示するに留める。

用語: 「簡易 stg」＝環境設計書 `stg`＝全体計画 `staging`（[受入環境方針](../../13_受入テスト/テスト計画/受入環境方針.md) の用語同定）。

## 4. 対象範囲（シナリオ）

全体計画 §7.5.2 を起点とする。MVP 最小として以下を必須候補とする（カットラインの最終確定は Human）。

| シナリオID | シナリオ | 必須候補 | 主な確認 |
| --- | --- | --- | --- |
| ST-001 | 初期表示導線 | ○ | マスタ取得（Orval client） |
| ST-002 | レコメンド実行導線 | ○ | 入力→API→Reco→Result→画面 |
| ST-003 | 商品詳細表示導線 | ○ | 詳細取得・表示 |
| ST-004 | Feedback 送信導線 | ○ | Feedback→DB |
| ST-005 | Batch 商品取込導線 | △ | fixture→Raw→Staging→Item（Layer2 fixture） |
| ST-006 | Batch Feature 生成導線 | △ | Queue→Semantic→Feature |
| ST-007 | Batch Embedding 生成導線 | △ | Embedding 保存 |
| ST-008 | Batch→Online 参照導線 | ○ | Batch 済みデータを Online 推薦で参照 |
| ST-009 | 0件結果導線 | ○ | 空結果／案内 |
| ST-010 | エラー導線 | ○ | timeout／DB 失敗時の安全応答・ログ |
| ST-011 | ログ追跡導線 | ○ | trace_id / run_id / batch_run_id |

○: MVP システムテスト合格に原則必須、△: データ準備状況に応じ必須化（Human 判断）。

## 5. 開始条件

| 条件 | 内容 | 確認の目安 |
| --- | --- | --- |
| コンポーネント結合完了 | 主要 IF が結合済み | 結合テスト／PR CI の主要合格 |
| API 契約検証合格 | OpenAPI／Orval／generated／typecheck | Layer1 PR CI |
| Layer2 実行可能 | `test-system.yml`（または同等）が dispatch 可能 | テスト環境設計書 |
| テストデータ／fixture | マスタ・商品・Feature・Embedding 相当が Layer2 fixture／seed で用意 | `tests/fixtures/` 等 |
| Batch→Online 前提 | Online が参照する Item／Feature／Embedding が fixture または事前生成で揃う | ST-008 |
| 環境変数正本 | 変数名が [環境変数定義書](../../06_実装設計/cross_cutting/環境変数定義書.md) と整合 | secret 実値は CI Secrets のみ |
| E3／外部 API 前提 | 外部 HTTP は **既定 off（fixture）**。限定 live は明示フラグのみ | Epic #1598 CLOSED／[バッチ外部API本実装ギャップ一覧](../../05_アプリケーション設計/アプリ/batch/バッチ外部API本実装ギャップ一覧.md) |

### 5.1 E3 ゲート（参照）

| 項目 | 方針 |
| --- | --- |
| システムテスト開始 | **fixture／Scaffold 経路で主要導線が通ること**を必須とする |
| 楽天／Embedding／Storage live | システムテスト合格の必須条件にはしない（既定 off） |
| live 再確認 | 必要時のみ stg または明示フラグ。CI／Layer2 既定 live 禁止 |
| DB 読取未配線等 | ギャップ一覧の残件はブロッカー表（§7）で扱い、無理に本計画で実装しない |

## 7. ブロッカー定義

| 区分 | 例 | 扱い |
| --- | --- | --- |
| Blocker | 推薦実行が安定しない、生成 client 経路が壊れている、Layer2 が実行不能 | システムテスト未完了。後工程（品質／受入）に進まない |
| 既知ギャップ | Batch 一部の DB SELECT 未配線、live 未実施 | ギャップ一覧を参照し、ST シナリオを fixture で代替可能か Human 判断 |
| 環境 | stg 未構築 | Layer2 主実施のため **Blocker にしない**（受入は別途簡易 stg 必須） |
