## 1. 目的

本ドキュメントは、本サービスにおける実行環境の構成方針を定義し、以下を明確化することを目的とする。

- 開発・検証・本番の環境分離方針
- 各環境に配置するコンポーネント
- 環境ごとの役割と品質水準
- データ・設定・認証情報の分離方針
- 後続の DevOps / CI/CD / 運用設計の前提

---

## 3. 環境設計の基本方針

### 3.1 基本方針

```
・環境ごとに役割を明確に分ける
・本番と非本番は必ず分離する
・環境差分は最小化しつつ、品質ゲートは段階的に高める
・Secrets / DB / Cache は環境ごとに分離する
・アプリ設定はコード埋め込みではなく環境設定で切り替える
```

### 3.2 役割の原則

| 環境 | 主目的                   |
| ---- | ------------------------ |
| dev  | 実装・動作確認           |
| stg  | リリース前検証・結合確認 |
| prod | 実利用サービス提供       |

---

## 4. 環境一覧

## 4.1 環境定義

| 環境             | 論理名 | 目的                               |
| ---------------- | ------ | ---------------------------------- |
| 開発環境         | dev    | 実装・単体確認・疎通確認           |
| ステージング環境 | stg    | 本番前検証・結合確認・簡易性能確認 |
| 本番環境         | prod   | ユーザー提供用                     |

---

## 4.2 MVP方針

### 事実

MVP段階では、環境を増やしすぎると運用コストが上がる。

### 推論

そのため MVP では、

```
dev / prod を先行整備し、
stg は必要に応じて導入、または簡易構成で開始する
```

でもよい。

ただし、**本番前検証の場は必ず確保する**。

## 7. 環境別データ方針

## 7.1 DB分離

```
・環境ごとにDBを分離する
・prodデータをdev/stgで直接共有しない
```

### 理由

- 誤更新防止
- 検証データ混入防止
- セキュリティ確保

---

## 7.2 Redis分離

```
・環境ごとにRedisを分離する
・prod cache を dev/stg と共有しない
```

---

## 7.3 データ投入方針

| 環境 | 方針                             |
| ---- | -------------------------------- |
| dev  | サンプルデータ / 小規模データ    |
| stg  | 本番準拠データ（匿名化・縮小版） |
| prod | 正式データ                       |

## 17. 設計原則まとめ

```
・環境ごとに役割を分ける
・本番と非本番は必ず分離する
・設定差分は環境変数で吸収する
・品質要求は dev < stg < prod の順に高める
・MVPでは最小構成で開始し、必要に応じて stg を強化する
```

---

## 18. 一言まとめ

```
本サービスの環境設計は、
「開発効率」と「本番安全性」を両立するために、
dev / stg / prod を役割ごとに分離し、
構成差分を最小限に保ちながら品質ゲートを段階化する
```

## 19.1 秘匿性区分

| 区分            | 意味                                           | Git 管理 | client 公開 | 例                               |
| --------------- | ---------------------------------------------- | -------- | ----------- | -------------------------------- |
| `secret`        | 認証・接続に使う機密情報                       | 不可     | 不可        | `DATABASE_URL`, `OPENAI_API_KEY` |
| `config`        | 環境ごとに変わる非機密設定                     | 例示のみ | 原則不可    | `RECO_BASE_URL`, `LOG_LEVEL`     |
| `public-config` | ブラウザ公開してよい設定（Next.js 等）         | 例示のみ | 可          | `NEXT_PUBLIC_API_BASE_URL`       |
| `ci-secret`     | CI / Batch 実行時のみ利用する secret           | 不可     | 不可        | GitHub Actions Secrets 経由      |

Secret 管理の詳細ルールは [認証・認可方針書](../../05_アプリケーション設計/基盤/認証・認可方針書.md) §10.2 を正とし、本節では重複定義しない。

| `SUPABASE_SERVICE_ROLE_KEY` | secret | △     | Supabase 採用時の server-side 操作 | GitHub Actions Secrets        | 必須     | web へ公開禁止                                               |
