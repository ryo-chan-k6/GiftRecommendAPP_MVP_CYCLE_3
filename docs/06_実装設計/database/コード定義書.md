## 2. 概要

本ドキュメントは、Gift Recommendation Service MVP において **DB カラムで参照する業務コード**（enum ではない識別子・区分値）を定義する。

状態遷移・モード・Batch フェーズ名など **enum 定義書の対象**は `enum定義書.md` を正とし、本書では **重複定義しない**。

Phase2 では docs ブリッジとして本書を正本とし、機械可読実装正本は Phase4a `packages/code-definitions` で整備する（§4.2）。

---

## 3. 目的

- テーブル定義書で「code 未定義」とされていた DB カラムの許容値を正本化する
- DDL / migration Task が参照する CHECK 制約の前提を揃える
- `enum定義書.md`・`エラーコード定義書.md`・Phase4a `packages/code-definitions` との責務分担を明確にする

---

## 4. 定義方針

| 観点 | 方針 |
| ---- | ---- |
| 対象範囲 | DB 物理列として保持する **業務コード**（商品ソース、ランキング期間、画像サイズ、Error Log 分類等） |
| 対象外 | 状態 enum（`run_status` 等）、Semantic / Application enum、`error_code`（GRS 形式のみ DB 制約） |
| 正本（Phase2） | 本ドキュメント |
| 正本（Phase4a 実装） | `packages/code-definitions/**`（Human Review 後に YAML 化） |
| 命名 | 論理 ID は snake_case。DB 物理列名は各テーブル定義に従う |
| 値の追加 | migration + docs 更新 + Human Review |
| 値の変更 | 破壊的変更。既存行の UPDATE または再取込が必要 |
| MVP 拡張 | `product_source` は MVP `rakuten` 固定。将来 EC 追加時は CHECK 拡張 |

### 4.1 enum定義書との分担

| 区分 | 正本 | 例 |
| ---- | ---- | -- |
| 状態・モード・Batch enum | `enum定義書.md` + `packages/code-definitions/state|application|batch|semantic/` | `run_status`, `source_api`, `feedback_type` |
| 業務コード（本書） | 本ドキュメント | `source`（商品ソース）, `period`（ランキング期間） |
| エラーコード | `エラーコード定義書.md`（人間可読）+ Phase4a `error/`（機械可読） | `GRS-REC-001` |

同一物理列名でも意味が異なる場合は **別論理 ID** とする（`enum定義書.md` §4.1 と同型）。

### 4.2 Phase4a packages-foundation との関係

| レイヤ | 役割 | 本 Task |
| ------ | ---- | ------- |
| 本ドキュメント | Phase2 docs ブリッジ。DDL / seed 設計の参照正本 | **作成** |
| `packages/code-definitions/` | 実装・seed 生成・CI 整合の機械可読正本 | **未作成**（Phase4a Task） |
| `supabase/seeds/masters/` | マスタ投入 SQL | Task ⑤ / A4 移行 |

本 Task では `packages/` へのファイル追加は **out of scope** とする。

## 6. コード値定義

### 6.1 Product Source (`product_source`)

外部商品データ・Item 正本の **マーケット識別子**。`item.source` を起点に、同一コード体系を Raw / Staging / Log 系テーブルへ伝播する。

| 値 | 表示名 | 意味 | 利用条件 | 有効 / 無効 | 備考 |
| -- | ------ | ---- | -------- | ----------- | ---- |
| `rakuten` | 楽天市場 | 楽天 Ichiba API 由来の商品・ジャンル・属性データ | MVP 全外部商品連携 | `yes` | CHECK で MVP 固定 |

### 6.2 Ranking Period (`ranking_period`)

楽天商品ランキング API（API-EXT-002）の **期間区分**。`ranking_snapshot` を正として、派生シグナル表へ伝播する。

| 値 | 表示名 | 意味 | 利用条件 | 有効 / 無効 | 備考 |
| -- | ------ | ---- | -------- | ----------- | ---- |
| `realtime` | リアルタイム | リアルタイムランキング | BATCH-002 取得時 | `yes` | 楽天 API `period` に準拠 |
| `daily` | デイリー | 日次ランキング | BATCH-002 取得時 | `yes` | |
| `weekly` | ウィークリー | 週次ランキング | BATCH-002 取得時 | `yes` | |
| `monthly` | マンスリー | 月次ランキング | BATCH-002 取得時 | `yes` | |

### 6.3 Image Size Type (`image_size_type`)

楽天商品画像 URL の **サイズ区分**。BATCH-007 で `staging_item_image` → `item_image` へ転記する。

| 値 | 表示名 | 意味 | 利用条件 | 有効 / 無効 | 備考 |
| -- | ------ | ---- | -------- | ----------- | ---- |
| `small` | Small | 小サイズ画像 URL | 楽天 `smallImageUrls` | `yes` | API-PUB-003 応答でも利用 |
| `medium` | Medium | 中サイズ画像 URL | 楽天 `mediumImageUrls` | `yes` | 主画像候補は medium 優先（テーブル定義書 §5.3） |

### 6.4 Error Log Service (`error_log_service`)

`error_log` に記録する **発生サービス区分**。構造化アプリログ（§8.1）の `service` とは集合が異なる（`web` は DB 非保存）。

| 値 | 表示名 | 意味 | 利用条件 | 有効 / 無効 | 備考 |
| -- | ------ | ---- | -------- | ----------- | ---- |
| `api` | API | `apps/api` で検知したエラー | Public / Internal API 処理 | `yes` | ログ・Observability設計書 §9.2 |
| `reco` | Reco | `apps/reco` で検知したエラー | 推薦パイプライン | `yes` | |
| `batch` | Batch | `apps/batch` で検知したエラー | Batch ジョブ全般 | `yes` | |

### 6.5 Error Log Severity (`error_log_severity`)

`error_log` の **重大度**。エラーコード定義書の retryable / HTTP マッピングと併用する。

| 値 | 表示名 | 意味 | 利用条件 | 有効 / 無効 | 備考 |
| -- | ------ | ---- | -------- | ----------- | ---- |
| `warn` | Warning | 継続可能・要監視 | Rate Limit 等 | `yes` | |
| `error` | Error | 処理失敗 | 通常の業務エラー | `yes` | |
| `critical` | Critical | 即時対応 | Secret 検知・致命的障害 | `yes` | |

## 9. テーブル一覧・retention との関係

`テーブル一覧.md` §retention により、Log / Metric 系は保持期間を物理設計で定義する。

本書の `error_log_service` / `error_log_severity` は **error_log の分類列**であり、retention ポリシーそのものではない。保持期間・削除条件は後続 Task ⑥（データ保持・削除方針書）で確定する。

| 関連テーブル | 本書との関係 |
| ------------ | ------------ |
| `error_log` | `service` / `severity` の CHECK 正本は本書 |
| `phase_log` | 状態は enum（`phase_status`）。retention は §6.15 注記 |
| `api_call_log` | `source` は本書、`source_api` / `call_status` は enum |
