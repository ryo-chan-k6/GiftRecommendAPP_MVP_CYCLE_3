## 2. 目的

推薦結果・理由文・Feature / Meaning / Ranking が、贈答文脈に対して妥当であることを確認できる状態を定義する（全体計画 §7.7.1）。

リリース判定（§12.2「品質: 固定評価ケースで重大な推薦破綻がない」）の証跡欄を埋められる前提を揃える。

---

## 3. 実施環境の役割

| 環境 | 本計画での役割 | データ |
| --- | --- | --- |
| **Layer2 GHA** | **固定評価ケース**の自動メトリクス・回帰（`test-reco-quality.yml`） | fixture / 固定ケース |
| **簡易 stg** | **実運用想定の多様パターン**の人手レビュー | 縮小多様カタログ＋評価ケース |
| local | 探索・デバッグ。品質合格証跡には **数えない** | Mock 既定 |

### 3.1 全体計画 §7.7 との関係

全体計画 §7.7.3 は実施環境を `staging / evaluation用` と記載する。受入環境方針は品質を **固定＝Layer2／多様人手＝簡易 stg** に細分化する。

本計画はその細分化を採用する。全体計画本文への反映は後続 Task 候補とする。

用語: 「簡易 stg」＝環境設計書 `stg`＝全体計画 `staging`（受入環境方針の用語同定）。

## 4. 評価対象（観点）

全体計画 §7.7.2 を起点とする。

| 対象 | 確認内容 | ゲート候補 |
| --- | --- | --- |
| User Feature | relationship / occasion / pair 等が Feature に反映されるか | ○ |
| Item Feature | 商品由来 Feature が直感と大きく乖離していないか | △（人手） |
| Meaning Space | Social / Symbolic の位置づけが文脈に合うか | △（人手） |
| Retrieval | 候補が大きく文脈外れでないか | ○／△ |
| Matching | User×Item の一致度が妥当か | △ |
| Ranking | 上位が下位より文脈に合うか | ○／△ |
| MMR / 多様性 | 類似偏りがないか | △ |
| Reason | 理由が商品・文脈・Feature と矛盾していないか | ○ |
| NG 回避 | NG 条件商品の混入がないか | ○（必須） |
| 予算適合 | budget 範囲外が上位に出ないか | ○（必須） |
| 分布妥当性 | Feature / score 分布の極端な偏りがないか | △（自動メトリクス） |

○: リリースゲートに近い必須、△: 人手／分布で補強（件数・合格ラインは Human 確定）。

## 5. 固定評価ケース方針（草案）

| 項目 | 方針（草案） | Human 確定 |
| --- | --- | --- |
| 目的 | 再現可能な入力で重大破綻・NG・予算違反を検出する | — |
| 含む軸 | relationship / occasion / pair / budget / NG 条件 | [ ] 必須軸の最終リスト |
| 件数 | MVP 初期は **少数の代表ケース**（目安 10〜30。最終は Human） | [ ] 件数 |
| 期待 | 「正解ランキング1つ」ではなく **破綻・違反の有無** と観点メモ | [ ] 合格ライン文言 |
| 保存 | `evaluation_dataset` / `evaluation_case` または同等の正本管理 | — |
| Layer2 | 同一固定ケースを `test-reco-quality.yml` で回帰 | — |

レコメンドは UX の単一正解が無いため、**探索（多様人手）** と **ゲート（固定ケース）** を分ける（受入環境方針と同趣旨）。

## 6. 重大な推薦破綻（定義草案）

以下のいずれかに該当する場合、**重大破綻**候補とする（最終定義は Human）。

| ID | 草案 | 備考 |
| --- | --- | --- |
| Q-NG-1 | NG 条件に該当する商品が推薦上位に混入する | 終了条件「NG混入なし」 |
| Q-BUDGET-1 | 上位推薦が budget_min / budget_max を明らかに外れる | 終了条件「予算違反なし」 |
| Q-REASON-1 | 理由文が商品・文脈・Feature と明白に矛盾する | 終了条件「理由文妥当」 |
| Q-CONTEXT-1 | 固定ケースにおいて、贈答文脈から見て明らかに不自然な商品が上位を占める | 「重大破綻なし」 |
| Q-EMPTY-1 | 正常入力なのに理由なく空結果・エラーのみとなる（システム不良と区別） | システム計画 ST-009/010 と連携 |

**未確定（Human）:** Q-CONTEXT-1 の「明らかに不自然」の判定者・サンプル数・許容件数。

見切れ分（主観の残り）は残課題としてリリース判断に載せ、無理に「全パターン合格」としない。

## 8. 終了条件

| 条件 | 内容 |
| --- | --- |
| 重大破綻なし | 固定評価ケースで §6 草案（Human 確定後）に該当する重大破綻がない |
| NG 混入なし | NG 条件商品が混入していない |
| 予算違反なし | 上位に予算範囲外が含まれていない |
| 理由文妥当 | 理由が商品・文脈・Feature と矛盾していない |
| 分布異常なし | Feature / score 分布に明らかな異常がない（自動メトリクス可） |
| 証跡 | §9 の置き場に結果要約がある |

多様人手レビューは「重大破綻の追加発見」と探索に使い、固定ケースゲートを代替しない。
