## 4. 環境別設定先

環境識別子は定義書 §4 に従う（`dev` / `stg` / `prod`。`stage` は使わない）。

### 4.1 local（開発マシン）

| 項目 | 手順 |
| --- | --- |
| 設定先 | 各 app またはリポジトリルートの `.env`（Git 管理外） |
| 雛形 | `.env.example` をコピーし、**ダミー／ローカル既定値のみ** を埋める |
| `APP_ENV` | `dev` |
| 禁止 | prod / stg の secret を置かない（受入環境方針 §8） |
| 外部 API | live は既定 off。明示フラグがある場合のみ、許可された検証用キーを使う |

参照: 定義書 §11（設定先マトリクス）、§12（`.env.example`）

### 4.2 簡易 stg（検証・受入）

| 項目 | 手順 |
| --- | --- |
| 設定先 | Web / API / Reco ホスティングの **stg Environment**、および必要なら GitHub Actions の stg 向け Secrets / Variables |
| `APP_ENV` | `stg` |
| `DATABASE_URL` | **stg 専用**。prod / local / Layer2 ephemeral と共有しない（受入環境方針 §7） |
| Web | `NEXT_PUBLIC_API_BASE_URL` 等を stg API 向けに設定（client に secret を含めない） |
| API / Reco | 定義書 §7・§8 の secret / config を Environment 単位で登録 |
| Batch / CI | 定義書 §10 の名前で Secrets / Variables を登録。値は stg 用のみ |

### 4.3 prod（本番）

| 項目 | 手順 |
| --- | --- |
| 設定先 | Web / API / Reco ホスティングの **prod Environment**、および本番用 GitHub Secrets / Variables |
| `APP_ENV` | `prod` |
| 分離 | stg と物理・論理とも secret を共有しない。同一文字列のコピペ再利用を避ける |
| 権限 | 登録・更新は人間（または承認済み運用）に限定。AI Agent は実値を扱わない |

### 4.4 GitHub Actions（CI / Batch）

| 項目 | 手順 |
| --- | --- |
| 登録 UI | リポジトリ Settings → Secrets and variables → Actions |
| 名前 | [環境変数定義書 §10](../../06_実装設計/cross_cutting/環境変数定義書.md) の対応表に従う（値は書かない） |
| Environment | workflow が Environment を使う場合、`stg` / `prod` を誤接続しないよう job / Environment 名を確認する |
| 既定 | `BATCH_OBJECT_STORAGE_LIVE` 等の live 系は既定 `0` / 未設定（定義書 §9・§10） |

ホスティング側の Secret 物理名は定義書 §10 と同一を推奨する。環境分離はプラットフォームの Environment 機能で行う。

## 6. 分離確認

登録後・受入前・リリース前に、次を満たすこと。

| # | 確認内容 | 根拠 | 確認 |
| --- | --- | --- | --- |
| S1 | stg の `DATABASE_URL` と prod の `DATABASE_URL` が同一でない | 受入環境方針 §7、定義書 §13 | [ ] |
| S2 | local `.env` に stg / prod の secret を置いていない | 受入環境方針 §8、定義書 §4・§13 | [ ] |
| S3 | 外部 API live（楽天・Embedding・Object Storage live 等）が既定 off | 定義書 §9・§10、受入環境方針 §8 | [ ] |
| S4 | Web に Service Role Key / OpenAI / 楽天キーを渡していない | 認証・認可方針書 §10.2 | [ ] |
| S5 | Git 管理下に `.env` 実体・secret 実値が含まれていない | 認証・認可方針書 §10.2 | [ ] |
| S6 | workflow / job の `APP_ENV` または Environment が意図した環境である | 定義書 §10 | [ ] |

確認方法の例（値はログに出さない）:

- ホスティング UI で Environment 名と変数 **名** の一覧のみを見る
- DB ホスト名の先頭・プロジェクト名の一致／不一致だけを目視する（接続文字列全体をコピーしない）
- `git status` / `git check-ignore` で `.env` が追跡されていないことを確認する

## 7. 簡易 stg 受入前の必須確認

受入証跡は簡易 stg 上の結果のみ有効（受入環境方針 §3・§8）。受入開始前に次を満たす。

| # | 確認内容 | 確認 |
| --- | --- | --- |
| A1 | §5・§6 の stg 向け登録・分離確認が完了している | [ ] |
| A2 | api / reco /（必要なら）batch が同一の stg `DATABASE_URL` を参照する方針になっている | [ ] |
| A3 | Web の API Base URL が stg API を指している | [ ] |
| A4 | local 合格をもって受入完了としていない | [ ] |
| A5 | 受入結果に「実施環境 = 簡易 stg」を残す準備ができている | [ ] |

インフラの実構築手順自体は本ドキュメントの範囲外。構築完了後の **env 観点のゲート** として使う。
