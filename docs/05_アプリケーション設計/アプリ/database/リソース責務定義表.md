# リソース責務定義表

## 1. 概要

### 1.1 目的

本ドキュメントは、Gift Recommendation Service MVP における各リソースの責務を定義する。

リソース一覧では、システムが扱う主要な業務データ単位を整理した。  
本ドキュメントでは、各リソースについて以下を明確にする。

- 何を保持する責務を持つか
- 何を保持しないか
- どのコンポーネントが主に生成・更新・参照するか
- 正本・派生・ログ・外部参照のどれとして扱うか
- API設計、DB設計、Batch設計、Reco詳細設計へどう接続するか

## 3. 責務定義の考え方

### 3.1 リソース責務とは

リソース責務とは、そのリソースがシステム上で担うデータ責務である。

```text
リソース責務
= そのリソースが保持・参照・表現・追跡すべき業務上の責任範囲
```

たとえば、`Recommendation Request` は「推薦入力条件を保持する責務」を持つ。  
一方で、`Recommendation Request` は「推薦候補を抽出する責務」や「Rankingを計算する責務」は持たない。

---

### 3.2 責務区分

| 責務区分       | 説明                                               | 例                                       |
| -------------- | -------------------------------------------------- | ---------------------------------------- |
| 入力正本       | ユーザーまたは評価処理から投入された入力条件の正本 | Recommendation Request                   |
| 実行正本       | 1回の処理実行単位・状態・Version固定情報の正本     | Recommendation Run                       |
| 出力正本       | ユーザーに提示した推薦結果の正本                   | Recommendation Result                    |
| 商品正本       | 推薦対象として扱う商品情報の正本                   | Item                                     |
| 商品外部参照   | 外部EC由来のURL・画像URLなどの参照情報             | Item Image / External EC Item Page       |
| 派生データ     | 正本や外部データから計算・生成される情報           | User Feature / Item Feature / Score      |
| 値オブジェクト | 親リソースの一部として扱う意味のある値のまとまり   | Budget Condition / Gift Context          |
| 参照データ     | 他リソースや外部データを参照するための情報         | Version Reference / Item Reference       |
| ログ           | 実行事実、エラー、行動、計測値の記録               | Phase Log / Error Log / Metric Log       |
| 外部原本       | 外部サービスから取得した原本データ                 | Raw Product JSON                         |
| マスタ         | 入力選択肢・分類・定義値                           | Relationship Master / Feature Definition |

---

### 3.3 管理主体

| 管理主体          | 主な責務                                                                                                            |
| ----------------- | ------------------------------------------------------------------------------------------------------------------- |
| web               | 入力・表示・Feedback入力                                                                                            |
| api               | HTTP受付、Validation、Request保存、Feedback保存、レスポンス整形                                                     |
| reco              | 推薦パイプライン、User Meaning生成、Retrieval、Matching、Ranking、Result生成、Reason生成                            |
| batch             | 商品データ取得、Raw保存、Staging変換、Item反映、Item Image反映、Item Feature生成、Embedding生成、Offline Evaluation |
| database          | 構造化データ、正本、派生データ、ログの保存                                                                          |
| object storage    | Raw Product JSON本体の保存                                                                                          |
| external services | 楽天市場商品検索API、外部AI API、外部EC商品ページ                                                                   |
| devops            | CI、Batch実行、運用自動化、改善Backlog連携                                                                          |

## 4.5 商品画像系リソース

## 7. 商品画像データの責務整理

### 7.1 商品画像データの基本方針

MVPでは、外部商品は楽天市場商品のみを対象とする。  
商品画像は、楽天市場商品検索APIから取得できる以下の画像URL参照データを利用する。

- `mediumImageUrls`
- `smallImageUrls`

MVPでは、以下は行わない。

- 画像バイナリ本体の保存
- 自前CDN配信
- 画像加工
- 画像解析
- 画像URLの死活監視

---

### 7.2 商品画像データの責務分担

| リソース                   | 責務                                                                            |
| -------------------------- | ------------------------------------------------------------------------------- |
| Raw Product JSON           | 楽天市場APIレスポンス原本として `mediumImageUrls` / `smallImageUrls` を保持する |
| Staging Item Image         | Raw内の画像URL配列を、Item Imageへ反映しやすい中間形式に変換する                |
| Item Image                 | 商品に紐づく画像URL参照データの正本として保持する                               |
| Primary Image URL          | 表示に使う代表画像URLを決定する                                                 |
| Recommendation Result Item | 表示時点の商品情報スナップショットを保持する                                    |
| Result Item Image Snapshot | 推薦結果で実際に表示した画像URLを保持する                                       |

---

### 7.3 商品画像データフロー

```text
楽天市場商品検索API
↓
Raw Product JSON
  - mediumImageUrls
  - smallImageUrls
↓
Staging Item Image
↓
Item Image
↓
Primary Image URL
↓
Recommendation Result Item
↓
Result Item Image Snapshot
↓
レコメンド結果一覧画面 / 商品詳細画面
```

---

### 7.4 表示画像の選択方針

| 条件                                 | 方針                                                          |
| ------------------------------------ | ------------------------------------------------------------- |
| `mediumImageUrls` が存在する         | 原則、先頭またはdisplay_order最小のmedium画像を代表画像にする |
| `mediumImageUrls` が存在しない       | `smallImageUrls` をfallbackとして利用する                     |
| 両方存在しない                       | 画像なし状態としてResult Itemに保持する                       |
| 複数画像がある                       | `display_order` で優先順位を管理する                          |
| Result生成後にItem Imageが更新された | 過去ResultではResult Item Image Snapshotを優先する            |

## 12. レビュー観点

| 観点             | 確認内容                                                                                        |
| ---------------- | ----------------------------------------------------------------------------------------------- |
| 責務分離         | Request / Run / Result / Feedbackの責務が混ざっていないか                                       |
| 正本・派生分離   | 正本リソースと計算結果・派生データが混ざっていないか                                            |
| 商品画像責務     | Item Image / Result Item Image Snapshot / Raw Product Image URLs の責務が分離されているか       |
| MVP整合          | 認証・履歴・購入・決済・配送・画像バイナリ保存がMVP対象に混入していないか                       |
| 処理構成整合     | Online / Batch / 共通 / 運用の処理責務と矛盾していないか                                        |
| 保存方針整合     | Raw JSON本体はObject Storage、Raw MetadataはDB、Item ImageはDBという方針に合っているか          |
| 推薦順序整合     | Pre Hard Filter → Retrieval → Post Hard Filter → Matching → Ranking → Result と矛盾していないか |
| Feedback改善接続 | FeedbackがEvaluation / Analysis / Improvement Backlogへ接続できるか                             |
| Version再現性    | Run / Resultにsemantic_config_version / model_versionが接続できるか                             |
| UI接続性         | 結果一覧、理由詳細、商品詳細、Feedback入力で必要なリソースがあるか                              |
| API接続性        | `POST /recommendations` とFeedback登録APIへ自然に展開できるか                                   |
| DB接続性         | 独立テーブル・親内項目・ログ・JSONの判断ができるか                                              |

```text
Recommendation Result
= ユーザーに提示した推薦結果の正本

Recommendation Result Item
= 推薦結果内の商品1件単位の正本

Result Item Image Snapshot
= 推薦結果表示時点の商品画像URL

Recommendation Reason
= UI表示・Reason Feedback対象となる推薦理由

Recommendation Feedback
= 推薦品質改善のための明示評価データ

Log / Metric
= 実行事実・異常・計測値の記録
```

初回MVPでは、以下を責務境界として固定する。

```text
- Requestは入力条件を保持する。推薦計算はしない。
- Runは実行状態とVersion固定を管理する。結果内容の正本ではない。
- Resultはユーザーに提示した内容を保持する。購入・決済・配送は扱わない。
- Result Itemは表示時点の商品情報・画像URLスナップショットを保持する。
- Feedbackは改善用評価データとして蓄積する。Rankingへ即時反映しない。
- Itemは内部商品正本であり、Raw JSON本体はObject Storageへ分離する。
- Item Imageは楽天市場商品検索API由来の画像URL参照データを保持する。
- 画像バイナリ本体、画像加工、CDN配信はMVPでは扱わない。
- Feature / Embedding / Scoreは派生データとして扱う。
- Config / Versionは推薦結果の再現性を確保するためRun / Resultへ紐づける。
```
