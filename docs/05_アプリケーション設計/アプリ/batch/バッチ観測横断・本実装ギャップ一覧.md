### 4.4 app phase → DDL `phase_name` マッピング（Wave 2 / Wave 4 共通化）

DDL `phase_log`（`owner_type=batch_run`）の `phase_name` は固定 CHECK（`batch_started`, `cursor_loaded`, …, `batch_completed`）。  
アプリの `plan` / `finalize` 等をそのまま INSERT すると CHECK 違反になる。

#### 事実（実装・#1701 / #1705）

共通 map は `apps/batch/src/batch/application/observability/mapping.py` の `DEFAULT_APP_PHASE_TO_DDL`（旧 `GENRE_SYNC_APP_PHASE_TO_DDL` を統合）。

| app phase | DDL `phase_name` | DB 書込 |
| --------- | ---------------- | ------- |
| `plan` | `batch_started` | する |
| `finalize` | `batch_completed` | する |
| DDL 同一名（`batch_started` … `summary_created` … `batch_completed`） | identity | する |
| それ以外（`fetch` / `adapt` / `open_run` 等） | （なし） | **しない**（in-memory `phase_logs` のみ + warn） |

| app status | DDL `phase_status` |
| ---------- | ------------------ |
| `succeeded` / `failed` / `started` / `skipped` | 同名 |
| それ以外（例: `partially_succeeded`） | `failed`（失敗扱い） |

- `detail_json.app_phase` にアプリ側 phase 名を保持する（secret 禁止）。
- `error_code` 形式は DDL どおり `^GRS-[A-Z]{3}-[0-9]{3}$`（例: `GRS-BAT-001`）。
- `MOD-RECO-028` / `029` は使用しない。

#### Human Review 観点

| 観点 | 内容 |
| ---- | ---- |
| 粒度 | MVP では run 開始/終了のみ DDL に写像。中間 phase（fetch 等）を DDL 許可値へ増やすか |
| 別名 | `plan`→`batch_started` / `finalize`→`batch_completed` の対応が運用上十分か |
| 部分成功 | `partially_succeeded` を `failed` 扱いにしている点の妥当性 |
| 拡張 | Wave 4 で共通 `DEFAULT_APP_PHASE_TO_DDL` に統合済み。中間 phase を DDL 許可値へ増やすかは別 Human Review |
