# 機能×モジュール対応表

## 1. 概要

### 1.1 目的

本ドキュメントは、Gift Recommendation Service MVP における **機能** と **画面/UI要素・実装モジュール** の対応関係を整理する。

`機能一覧.md` では、ユーザー価値・システム機能の観点で必要な機能を整理した。
`モジュール一覧.md` では、`web` は画面/UI領域として分離し、API / Reco / Batch は実行機能モジュールとして分解した。

本ドキュメントでは、その対応関係を明確化し、後続の以下成果物へ接続できる状態にする。

```text
- API一覧
- バッチ一覧
- インターフェース一覧
- モジュール別入出力定義表
- モジュール詳細設計書
- 実装タスク分解
```

---

### 1.2 本ドキュメントで整理する内容

```
- 各機能がどの画面/UI要素またはモジュールで実現されるか
- 各機能の主担当コンポーネントはどこか
- Online処理 / Batch処理 / 共通処理 / 運用処理のどれに該当するか
- MVP対象か、後続対象か
- 主要要素と補助要素の関係
- 後続のAPI一覧・バッチ一覧・入出力定義へ引き継ぐ観点
```

## 3. 基本方針

### 3.1 対応表作成方針

| 方針                                     | 内容                                                                                                  |
| ---------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| 機能を起点に整理する                     | ユーザー価値・システム機能を起点に、必要なモジュールを対応付ける                                      |
| 主担当を明確にする                       | `web` は画面/UI領域、api / reco / batch はモジュール領域として主担当を明示する                        |
| 主要要素と補助要素を分ける               | 機能を直接実現する画面/UI要素またはモジュールと、Repository / Client / Log等の補助要素を分ける        |
| Online / Batchを分離する                 | ユーザー同期処理と事前準備処理を混在させない                                                          |
| Recoは詳細化済み前提で扱う               | 推薦パイプライン機能は、Recoモジュール一覧へ展開できる粒度で整理する                                  |
| 商品データ連携は疑似差分取得を前提にする | 全件取得ではなく、更新順・ランキング・ジャンル別・既存商品再確認・棚卸しを組み合わせる                |
| 商品画像を明示する                       | 楽天商品検索API由来の `smallImageUrls` / `mediumImageUrls` を Item Image として扱う                   |
| ランキングAPIの責務を分離する            | ランキングAPIはItem正本ではなく、Popularity Signal取得元として扱う                                    |
| 状態更新を過剰にしない                   | 商品単位の中間状態を逐次DB更新せず、Batch単位・API単位・Raw単位・チャンク単位・終端状態中心に保存する |

---

### 3.2 処理種別

| 区分 | 内容                                          |
| ---- | --------------------------------------------- |
| OL   | ユーザー操作に同期して実行されるOnline処理    |
| BT   | 定期実行・手動実行されるBatch処理             |
| 共通 | OL / BT双方から参照・利用される処理           |
| 運用 | 開発・保守・改善・CI/CD・手動実行に関する処理 |

---

### 3.3 MVP対象区分

| 区分 | 内容                                    |
| ---- | --------------------------------------- |
| ○    | 初回MVPで実装対象                       |
| △    | MVPで最小限または任意対応。後続で詳細化 |
| ×    | 初回MVPでは対象外                       |

---

### 3.4 モジュールID併記方針

API / Reco / Batch の実行機能モジュールは、`モジュール一覧.md` の `MOD-API-NNN` / `MOD-RECO-NNN` / `MOD-BATCH-NNN` を併記する。`web` の画面・画面部品はモジュールIDを付与せず、画面一覧・画面仕様書・UIコンポーネント一覧で管理する。

## 17. まとめ

本対応表では、Gift Recommendation Service MVP の機能を、以下の実装モジュール群へ対応付けた。

```
画面機能
→ web page / component / modal / API client

API機能
→ controller / validator / application service / repository / reco client

推薦パイプライン機能
→ orchestrator / semantic extractor / feature estimator / retriever / matcher / final score calculator / ranker / reason generator

商品データ連携機能
→ BATCH-001〜BATCH-009 / fetch planner / rakuten client / diff detector / raw writer / staging transformer / item updater

商品意味推定機能
→ BATCH-010〜BATCH-016 / item semantic generator / item feature generator / feature normalizer / embedding generator

評価・改善機能
→ BATCH-018〜BATCH-019 / offline evaluation runner / metric calculator / feedback analyzer / failure analyzer

マスタ・設定機能
→ master repository / config resolver / version repository

ログ・運用機能
→ phase log writer / error log writer / batch log writer / CI workflow / batch execution workflow
```

特に、以下の設計前提を本対応表に反映している。

```
- Online推薦中に外部商品APIを呼ばない
- Retrieval前にPre Hard Filterを実行する
- Retrieval後にPost Hard Filterを実行する
- 商品データ取得は疑似差分取得を前提にする
- Raw JSON本体はObject Storage、Raw MetadataはDBに保存する
- 商品画像はItem Imageとして管理する
- 楽天ランキングAPIはItem正本ではなくPopularity Signalの取得元とする
- 商品単位の中間状態を逐次DB更新しない
```

この対応表をもとに、後続では既存の `API一覧`、`バッチ処理一覧`、`画面一覧`、`Recoモジュール一覧` と照合しながら、`インターフェース一覧`、`モジュール別入出力定義表`、個別仕様書へ展開する。
