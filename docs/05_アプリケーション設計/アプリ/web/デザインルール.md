# デザインルール

## 1. 概要

### 1.1 目的

本ドキュメントは、Gift Recommendation Service MVP における Web UI の統一ルールを定義する。

贈答シーンの意味に基づくギフト推薦というドメイン特性を踏まえ、ユーザーが条件入力から推薦結果確認まで迷わず進める UI を、過剰な装飾なく一貫して提供することを目的とする。

本ドキュメントでは、以下を定義する。

- デザイン原則
- カラー・タイポグラフィ・余白などのデザイントークン
- ボタン、入力部品、カード、モーダル等の部品スタイル方針
- 画面状態（ローディング、エラー、0件）の表現方針
- 実装配置との対応（後続 Task 向け）

---

### 1.2 本ドキュメントの位置づけ

| 成果物               | 本ドキュメントとの関係                               |
| -------------------- | ---------------------------------------------------- |
| 画面一覧             | 画面単位の表示・入力要件の前提                       |
| 画面遷移図           | 画面状態・モーダル表示の前提                         |
| UIコンポーネント一覧 | 部品単位の責務定義。本ルールを部品実装へ落とし込む   |
| 利用技術スタック整理表 | web 技術選定（Next.js / React / TypeScript）の前提 |
| GiftRecommendAPP_LP | ビジュアル基準（色・フォント・トーン）。§2.3 参照 |
| styles-foundation（W3）| 本ルールのトークンを `apps/web/src/styles/**` へ実装 |

## 2. デザイン原則

### 2.1 基本方針

| 原則                 | 内容                                                                 |
| -------------------- | -------------------------------------------------------------------- |
| 体験優先             | 「意味でギフトを選べる」価値が伝わる情報設計を優先する               |
| 入力から結果まで明快 | 条件入力 → 実行中表示 → 結果一覧の導線を短く保つ                     |
| 過剰装飾を避ける     | MVP ではブランド演出より可読性・操作性を優先する（制約・対象外一覧） |
| 一貫性               | 色・余白・部品スタイルを共通トークンで統一する                       |
| 状態を明示する       | loading / error / empty を独立した視覚パターンで表現する             |
| アクセシビリティ基礎 | コントラスト、フォーカス表示、ラベル付与の最低限を満たす             |
| 実装還元を前提       | 画面実装で生じた共通パターンは UI コンポーネントへ還元する           |

### 2.2 MVP で重視する UX 観点

| 観点           | 方針                                                           |
| -------------- | -------------------------------------------------------------- |
| 信頼感         | 贈答用途にふさわしい落ち着いたトーン。温かみのあるニュートラル＋ブラウン系（LP 準拠） |
| 推薦理由の可読性 | 理由テキスト・注意文を本文と同等の視認性で表示する           |
| エラー時の復帰 | 入力修正・再実行への導線を明確にする                           |
| 外部 EC 遷移   | 購入は本サービス外であることを視覚的にも補助する（注意書き等）   |

### 2.3 ビジュアル基準（LP リポジトリ）

MVP Web アプリの全体トーンは、別リポジトリで公開している LP（**OKURI 贈**）のビジュアルを基準とする。

| 項目 | 内容 |
| ---- | ---- |
| 参照リポジトリ | [GiftRecommendAPP_LP](https://github.com/ryo-chan-k6/GiftRecommendAPP_LP) |
| 公開 URL | https://ryo-chan-k6.github.io/GiftRecommendAPP_LP/ |
| 正本ファイル | リポジトリ内 `index.html` の CSS 変数（`:root`）およびコンポーネントスタイル |
| 適用方針 | 色・フォント・ボタン・カードの雰囲気を LP と揃える。画面固有レイアウトはアプリ UX に合わせて調整してよい |
| 実装反映 | W3 `styles-foundation` で Tailwind theme / CSS 変数へマッピングする |

LP が示すブランドイメージは、**クリーム系の明るい背景**、**深いブラウンを主アクション**、**ゴールドをアクセント**、**明朝系フォント**による落ち着いた贈答体験である。

## 3. 技術前提

### 3.1 スタイリング方針

| 項目           | Phase4a 方針                                                     | 備考                                       |
| -------------- | ---------------------------------------------------------------- | ------------------------------------------ |

| グローバル样式 | `apps/web/src/styles/`                      |
| 画面ルーティング | `apps/web/src/app/`（本 Task の out of scope） |

## 4. デザイントークン

### 4.1 カラー

セマンティックカラーを正とする。具体値は LP リポジトリ（`GiftRecommendAPP_LP` / `index.html`）の CSS 変数を MVP 初期値とし、W3 で Tailwind theme へマッピングする。

| トークン名 | LP 変数名 | hex（MVP 初期値） | 用途 |
| ---------- | --------- | ----------------- | ---- |
| `color-bg` | `--cream` | `#FAF7F2` | ページ背景 |
| `color-surface` | — | `#FFFFFF` | カード・モーダル面（LP の gift-card 等） |
| `color-surface-muted` | `--parchment` | `#F2EDE3` | セクション背景・強調ブロック |
| `color-text` | `--ink` | `#2A1F18` | 本文・見出し |
| `color-text-secondary` | `--warm-brown` | `#8B6F5E` | リード文・ナビリンク |
| `color-text-muted` | `--muted` | `#9A8F86` | 補助文・キャプション |
| `color-primary` | `--deep-brown` | `#4A3728` | 主アクション（CTA・レコメンド実行） |
| `color-primary-hover` | `--ink` | `#2A1F18` | 主アクションホバー |
| `color-on-primary` | `--cream` | `#FAF7F2` | primary 上の文字色 |
| `color-accent` | `--gold` | `#C9A96E` | ラベル・強調・スコアバー等 |
| `color-accent-light` | `--gold-light` | `#E8D5B0` | アクセントの薄い版・下線等 |
| `color-border` | `--fog` | `#D4CFC8` | 枠線・区切り |
| `color-success` | `--sage` | `#7A8C6E` | 成功・完了（限定的利用） |
| `color-warning` | `--gold` | `#C9A96E` | 注意・推薦理由の caution |
| `color-error` | `--dusty-rose` | `#C4857A` | エラー・バリデーション |
| `color-focus` | `--gold` | `#C9A96E` | フォーカスリング（`:focus-visible`） |

**禁止・制約**

- 本文と背景のコントラスト比は WCAG 2.1 AA（4.5:1 目安）を意識する
- エラー色のみで意味を伝えず、文言を併用する
- LP と大きく乖離する高彩度の原色（純粋な青・赤ボタン等）は MVP では避ける

### 4.2 タイポグラフィ

| トークン名     | 用途           | サイズ目安（rem） | ウェイト | 行間目安 |
| -------------- | -------------- | ----------------- | -------- | -------- |
| `text-display` | トップ見出し   | 1.75〜2.0         | 600〜700 | 1.3      |
| `text-h1`      | 画面タイトル   | 1.5               | 600      | 1.35     |
| `text-h2`      | セクション見出し | 1.25            | 600      | 1.4      |
| `text-h3`      | 小見出し       | 1.125             | 600      | 1.45     |
| `text-body`    | 本文           | 1.0               | 400      | 1.6      |
| `text-small`   | 補助・キャプション | 0.875         | 400      | 1.5      |
| `text-label`   | フォームラベル | 0.875             | 500      | 1.4      |

**フォントファミリー（LP 準拠）**

| 用途 | フォント | 備考 |
| ---- | -------- | ---- |
| 本文・UI 全般 | **Noto Serif JP** | LP と同一。Google Fonts から読み込み |
| 見出し・ロゴ・強調 | **Shippori Mincho** | LP の `.hero-title` / `.section-title` 等と同一 |
| フォールバック | `'Hiragino Mincho ProN', serif` | LP と同様 |

- W3 では `next/font/google` 等で Web アプリ向けに最適化して読み込む（実装詳細は `styles-foundation` で定義）
- ゴシック体への切り替えは MVP では行わない（LP との一貫性を優先）

**タイポグラフィの雰囲気**

- 行間は LP に合わせ、本文は `line-height: 1.8` 前後を基準とする
- セクションラベルは LP の `.section-label` と同様、小さめ・字間広め（`letter-spacing: 0.2em` 程度）＋ゴールドのアクセントラインを任意で使用してよい

### 4.3 余白（スペーシング）

4px ベースのスケールを用いる。

| トークン | 値   | 主な用途                     |
| -------- | ---- | ---------------------------- |
| `space-1` | 4px  | アイコンとラベル間           |
| `space-2` | 8px  | 部品内パディング（小）       |
| `space-3` | 12px | フォーム項目間（密）         |
| `space-4` | 16px | 標準パディング・項目間       |
| `space-6` | 24px | セクション内ブロック間       |
| `space-8` | 32px | セクション間                 |
| `space-12`| 48px | ページ上下マージン（モバイル） |
| `space-16`| 64px | ページ上下マージン（デスクトップ） |

### 4.4 角丸・影・枠線

| トークン        | 値の目安        | 用途                         |
| --------------- | --------------- | ---------------------------- |
| `radius-sm`     | 2px             | ボタン（LP `.btn-primary` 準拠） |
| `radius-md`     | 8px             | カード・入力グループ         |
| `radius-lg`     | 12px            | モーダル・大きなカード       |
| `shadow-sm`     | `0 4px 24px rgba(42,31,24,0.08)` 相当 | カード |
| `shadow-md`     | `0 8px 40px rgba(42,31,24,0.12)` 相当 | モーダル・浮遊カード |
| `border-width`  | 0.5〜1px        | 入力・カード枠（LP は 0.5px 多用） |

## 5. レイアウト

### 5.1 ページコンテナ

| 項目           | ルール                                                       |
| -------------- | ------------------------------------------------------------ |
| 最大幅         | コンテンツ種別に応じて `max-w-screen-md`（フォーム）〜 `max-w-screen-lg`（結果一覧） |
| 水平パディング | モバイル `space-4`、デスクトップ `space-6` 以上              |
| 縦方向リズム   | セクション間は `space-8` を基本                              |

### 5.2 レスポンシブ方針

| ブレークポイント | 方針                                           |
| ---------------- | ---------------------------------------------- |
| モバイル優先     | MVP 主導線はスマートフォン幅を第一に設計する   |
| タブレット以上   | 結果一覧は 2 列カードまで。フォームは 1 列維持 |
| 横スクロール     | 原則禁止。表形式は MVP では避ける              |

## 6. インタラクティブ部品

### 6.1 ボタン

| バリアント   | 用途                         | スタイル方針                                      |
| ------------ | ---------------------------- | ------------------------------------------------- |
| `primary`    | 主アクション（レコメンド実行） | `color-primary`（`#4A3728`）背景、`color-on-primary` 文字。LP `.btn-primary` 準拠 |
| `secondary`  | 副アクション（戻る、閉じる） | 枠線（`color-border`）または `color-surface-muted` 背景 |
| `ghost`      | テキストリンク的アクション   | 背景なし、`color-text-secondary`。LP `.btn-ghost` 準拠 |
| `danger`     | 破壊的操作（MVP では限定的） | `color-error` 系。MVP ではほぼ未使用             |

| 状態     | ルール                                           |
| -------- | ------------------------------------------------ |
| default  | 上記バリアントに従う                             |
| hover    | primary は `color-primary-hover`（`#2A1F18`）へ。軽い `translateY(-1px)` は LP に合わせて可 |
| focus    | `color-focus` のリングを表示（`:focus-visible`） |
| disabled | 不透明度低下、クリック不可、`cursor-not-allowed` |
| loading  | スピナー表示、二重送信防止のため disabled 相当   |

**サイズ**

| サイズ | 高さ目安 | 用途               |
| ------ | -------- | ------------------ |
| `md`   | 40px     | 標準（フォーム送信） |
| `sm`   | 32px     | カード内・副次操作 |
| `lg`   | 48px     | トップの CTA       |

### 6.2 フォーム入力

| 部品種別     | ルール                                                                 |
| ------------ | ---------------------------------------------------------------------- |
| テキスト入力 | ラベル必須。placeholder は例示のみ。補助文はラベル下                  |
| 数値入力     | 予算欄。単位（円）をラベルまたはサフィックスで明示                     |
| セレクト     | relationship / occasion。マスタ取得失敗時はエラー表示                 |
| テキストエリア | preferred / non_preferred / ng。複数行、最小高さ 3 行相当            |
| エラー表示   | フィールド直下に `color-error` + `text-small`。アイコンのみに依存しない |

**バリデーション表示タイミング**

- 送信時（レコメンド実行ボタン押下）に一括検証を基本とする
- 個別フィールドの onBlur 検証は Phase4b 画面実装で必要に応じて追加

### 6.3 カード

推薦結果商品（SCR-004 / SCR-006）で使用する。

| 要素       | ルール                                           |
| ---------- | ------------------------------------------------ |
| 構成       | 画像（あれば）・商品名・価格・推薦理由要約・操作 |
| 画像       | アスペクト比固定、欠損時はプレースホルダ         |
| ホバー     | `shadow-sm` → `shadow-md` の軽い変化（任意）     |
| クリック領域 | 商品詳細へ遷移する領域を明確にする             |

### 6.4 モーダル

推薦理由詳細（SCR-005）、Feedback 入力（SCR-007）で使用する。

| 項目         | ルール                                           |
| ------------ | ------------------------------------------------ |
| オーバーレイ | 半透明の暗幕。背面スクロールはロック             |
| 閉じる操作   | 明示的な閉じるボタン + Esc キー（実装時）        |
| 幅           | モバイルは全幅に近い、デスクトップは `max-w-lg`  |
| フォーカス   | 開いた直後にモーダル内へフォーカス移動           |

## 7. 画面状態の表現

画面一覧の「画面状態」「モーダル / 部品」に対応する視覚パターンを定義する。

| 状態 ID | 名称               | 対応画面   | 表現方針                                           |
| ------- | ------------------ | ---------- | -------------------------------------------------- |
| ST-LOAD | ローディング       | SCR-003    | スピナー + 短い説明文。「推薦を実行しています」  |
| ST-ERR  | エラー             | SCR-008    | Alert（error）。原因の要約 + 再試行・戻る導線      |
| ST-EMPTY| 0件結果            | SCR-009    | EmptyState。条件変更を促す文言 + 入力画面への導線  |
| ST-NF   | Not Found          | SCR-014    | 簡潔なメッセージ + トップへ戻る（後続実装）        |

**エラーメッセージ方針**

- ユーザー向けには技術詳細（stack trace、HTTP status の生値）を表示しない
- API 共通エラー形式（`apps/api` 側）と文言マッピングは画面実装 Task で詳細化する

## 8. アクセシビリティ（MVP 最低限）

| 観点           | ルール                                               |
| -------------- | ---------------------------------------------------- |
| ラベル         | すべての入力に `<label>` または `aria-label`         |
| フォーカス     | キーボード操作で全インタラクティブ要素に到達可能     |
| コントラスト   | §4.1 を参照                                          |
| 動き           | アニメーションは控えめ。`prefers-reduced-motion` 考慮は W3 以降 |
| 画像           | 意味のある画像に `alt`。装飾画像は空 alt             |
