# MVPスコープ定義書

## 1. 概要

### 1.1 目的

- MVP（Minimum Viable Product）のスコープを定義する
- 価値仮説を最小コストで検証するための対象機能・非対象機能を明確化する

## 2. 前提整理

### 2.1 検証対象の価値仮説（再掲）

- ユーザーは「意味（Social × Symbolic）」を可視化することで意思決定できる

### 2.2 検証対象ユーザー

- 意味重視×迷い層（S01）

## 3. MVPの目的

### 3.1 検証目的

- 意味ベースレコメンドが意思決定に寄与するか検証する

### 3.2 検証したい問い（重要）

| ID  | 検証問い                         |
| --- | -------------------------------- |
| Q01 | 意味可視化で選択できるか         |
| Q02 | 意味スコアは理解されるか         |
| Q03 | リスク指標は意思決定に影響するか |

## 4. MVPスコープ定義

### 4.1 対象機能（In Scope）

| 機能ID | 機能名           | 概要                   |
| ------ | ---------------- | ---------------------- |
| F01    | レコメンド入力   | ユーザー条件入力       |
| F02    | 意味推定         | 入力から意味特徴量生成 |
| F03    | 商品検索         | 候補商品取得           |
| F04    | 意味スコアリング | Social / Symbolic算出  |
| F05    | ランキング       | スコアに基づく並び替え |
| F06    | 結果表示         | 商品＋意味スコア表示   |

### 4.2 非対象機能（Out of Scope）

| 分類         | 内容                  |
| ------------ | --------------------- |
| 決済         | 購入機能              |
| 配送         | 配送管理              |
| 会員管理     | ログイン/ユーザー管理 |
| 高度UI       | デザイン最適化        |
| 高精度モデル | 精度チューニング      |

## 5. スコープ境界（重要）

### 5.1 やること

- 意味で選べる体験を提供する
- 仮説検証に必要な最小機能を実装する

### 5.2 やらないこと

- 完全なEC体験
- 精度最大化
- UX最適化

## 6. 機能詳細（MVPレベル）

### 6.1 レコメンド処理フロー

```mermaid id="q7xn4r"
flowchart LR
    A[ユーザー入力] --> B[意味推定]
    B --> C[商品検索]
    C --> D[スコアリング]
    D --> E[ランキング]
    E --> F[結果表示]
```

### 6.2 スコアリング簡易仕様（MVP）

- Symbolic：意味一致度
- Social：安全性
- Risk：簡易ペナルティ

```text id="v0qgwe"
score = symbolic × social - risk
```

## 7. データスコープ

### 7.1 使用データ

| 種別       | 内容           |
| ---------- | -------------- |
| 商品データ | 楽天API等      |
| テキスト   | 商品名・説明   |
| メタデータ | カテゴリ・タグ |

### 7.2 非対象データ

- 画像解析（初期は除外）
- レビュー詳細解析（簡易利用のみ）

## 8. 技術スコープ

### 8.1 使用技術（MVP）

| 領域       | 技術                  |
| ---------- | --------------------- |
| フロント   | Next.js               |
| API        | Express               |
| レコメンド | FastAPI               |
| DB         | PostgreSQL + pgvector |
| Embedding  | OpenAI                |

### 8.2 非対象

- マイクロサービス分割
- スケーリング設計
- 高可用性構成

## 9. KPI仮説

### 9.1 行動指標

| 指標     | 目的         |
| -------- | ------------ |
| CTR      | 関心度       |
| CVR      | 意思決定成功 |
| 選択時間 | 効率性       |

### 9.2 成功基準（仮）

- CTR向上
- 意思決定時間短縮
- 定性評価で「選びやすい」

## 10. リスク・前提条件

### 10.1 リスク

| リスクID | 内容               | 対応               |
| -------- | ------------------ | ------------------ |
| R01      | 意味が理解されない | UI改善             |
| R02      | 精度不足           | 仮説検証と割り切る |

### 10.2 前提条件

- 低精度でも価値検証は可能
- ユーザーは意味で判断したい
